# jxcl-hardware

Top-level facade integrating the HDL AST, both text backends, and the toy synthesis pass behind one emit API.

## Honesty boundary

Composing real code does not make the result more verified than its
parts. Nothing in this crate simulates the emitted Verilog/VHDL, and
nothing feeds it to a real logic synthesizer -- there is no `iverilog`,
`verilator`, or `yosys` in this environment (see
`docs/HARDWARE_LIMITATIONS.md` at the workspace root).

`emit_netlist` is explicit about scope: `jxcl-synthesis`'s toy pass only
handles a narrow 2:1-mux-shaped case statement, and **none of the three
real core datapath modules generated by `jxcl-rtl` currently fit that
shape** (the decoder has one arm per real opcode, dozens rather than
two; the ALU/register-file modules carry no top-level case statement at
all yet). `NetlistReport`'s three fields are therefore all legitimately
`Err` today, and a test (`netlist_report_honestly_reports_out_of_scope_modules`
in this crate, and its `jxcl-hardware-test` counterpart) checks that
fact mechanically rather than leaving it as an unverified doc claim.
`emit_netlist_for` is provided so a caller can still run the toy pass on
a module that *does* fit its scope (e.g. `jxcl-hdl`'s canonical `mux2`
example).
